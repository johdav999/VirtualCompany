## Route and access decisions

- Home is `/dashboard?companyId={c}&lens={lens}`. CEO/company uses `company`; Finance/accounting uses `finance`; Support uses `customers`. Labels never create membership roles. `period=month&year={y}&month={m}` retains existing Monthly. Today removes monthly parameters. No second home or report engine.
- Active memberships feed the company selector. A company switch clears the old lens, month, restricted links and contextual agent, then starts Today using that company's server-resolved default. The existing `auth/select-company` owner persists selected company; no new view preference, entity or migration is added.
- `CompanyTodayWorkspaceLensResolver` owns permitted views and defaults; Monthly reuses it. Explicit responsibility assignment takes priority over membership fallback. An active member without an assignment gets the safe company fallback and its server explanation. Unavailable requested lenses canonicalize to the authorized default; invalid company memberships show restricted state. API policy remains authoritative for all records, summaries, commands and exports.
- Workspace and sidebar links carry company, record/filter context and one validated local `returnUrl` for the exact Overview. The Overview sidebar/brand uses `OverviewNavigationContext` within the current circuit and the URL on reload. It resets by company. Existing inner module links without `returnUrl` still retain the circuit origin; a fresh circuit at such an inner URL starts Today. Their durable nested-return improvements belong to the module journey prompt. No stored cross-company view state.
- Compatibility pages remain authorized by their existing handlers. Restricted utilities and public/guest routes retain their own entry points. Unknown/external destinations are not accepted as workspace return links.

## Design and evidence conventions

Design keys are repository-relative under `docs/design/references/`: D01=`role-time-agent-2026-10-01/01-ceo-today.png`, D02=`.../02-sales-today.png`, D05=`.../05-support-now.png`, DM=`responsibility-driven-monthly-workspace-reference.png`, DS=`app-shell-navigation-reference.png`, DF=`finance-dashboard-reference.png` if present, DA=`accounting-reports-close-reference.png`, DP=`sales-deal-detail-reference.png`, DK=`marketing-workspace-complete-reference.png`, DU=`support-cases-reference.png`, DW=`work-center-reference.png`, DT=`agent-team-kanban-reference.png`, DC=`.../08-agent-collaboration.png`, DG=`.../09-autonomy-controls.png`, DY=`.../06-ceo-year.png`, DL=`.../07-ceo-multiyear.png`. Ellipsis in these keys means the same `role-time-agent-2026-10-01/` directory, not an actual filename. Missing/new detail references must be generated before the owning prompt's major UI change; Finance Today and Marketing Today require separate references before P06/P05.

Evidence states are independent: **S** = shell implemented; **E** = existing page/panel preserved, journey completion unverified by P01; **N** = planned new implementation, not shipped. **A1** = P01 automatic navigation/access checks; **B1** = P01 isolated browser shell checks (see UAT packet for exact limits); **—** = not verified for this row. All **human approval = pending**. S is never a claim of complete P03–P08 content. Screenshots and scenarios are referenced by packet ID, not fabricated approval.

**A3** = P03 focused API/Web/Finance/typed-wire checks (109/51/5/3); **B3** = isolated real browser/API fixture journeys F03-01–06. Source/provider, SQL Server, deployed-tenant and human/statutory approval are separate gates. See `docs/verification/vcscreens/P03/`; a rendered unavailable Finance state is not cash-provider acceptance.
