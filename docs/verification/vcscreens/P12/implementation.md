# Implementation

One `DecisionReview` component serves Work and legacy Approvals. It shows proposal, affected records/recipients, allowlisted explicit before/proposed evidence, source links, policy, named reviewer, expiry, state and retained actor/time/note history. Missing evidence is explicit. Source navigation uses bounded same-company `decisionReturnUrl`, canonical approval `itemId`, and task `taskId`; P11 exact artifact/list return is retained. Agent work keeps terminal decision history links without inventing another outcome or Waiting state.

The existing approval identity/decision chain stores immutable material SHA256 evidence and additive review tokens. No schema/migration is needed. Hashes bind typed task/action/invitation/meeting-change/marketing/Finance-write/workflow material, immutable contribution versions and typed handoffs. Other owner bindings and execution checks remain authoritative. Existing legacy records explicitly lack creation evidence; a supplied observed token still detects changes. Before/after values are never fabricated from arbitrary provider payloads.

Decision commands retain required reviewer and segregation-of-duties rules, validate changes notes, recheck company/source scope and expiry, invalidate changed proposals and audit reviewer/scope/material changes. A serializable relational transaction claims the existing optimistic concurrency token before owner execution; request-id replay binds actor/step/decision/note and cannot advance the chain twice. Approved state is separate from owner execution status. Task material updates/reassignment invalidate pending and approved original reviews and ancestry. ChangesRequested records actor/time/note on the existing step and blocks the original owner target. Sales dispatch also checks exact approval target identity; existing provider/outbox/idempotency and Finance/Marketing authorities remain.

Production offline approval transport fails unavailable, rather than producing sample successful decisions. Opening or refreshing never decides or dispatches. The controlled adapter lives only in the bounded UAT test project.
