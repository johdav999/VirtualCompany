## Reconciliation and limits

Run `./docs/verification/vcscreens/P10/reconcile.ps1` while the local adapter is running. It makes GET requests only and refuses non-local base URLs. It reads current durable IDs, checks board/detail/Work/case/deal/summary consistency, seven counts, duplicate suppression, pagination and responsibility/company denial, and stores each source response with SHA-256 in `reconciliation/results.json`. It does not create or modify work. The 2,000-per-family partial source window and old known-ID detail are tested automatically; the browser fixture is smaller and does not claim a live 2,001-row journey.

Accepted automatic runs are the final TRX files named in `verification.json`. Diagnostic failed runs are retained for traceability and are not acceptance evidence. One UAT rebuild hit locked DLLs while its owned adapter was running; stopping that exact process and rebuilding succeeded. Final case regression covers New, customer/internal wait, approval, resolved and reopened states. A final 24-check API lifecycle/scope replay verifies permitted unlinked department outcomes and excludes hidden company dependency names/IDs. Accepted API coverage is 60 distinct tests, including overlapping replays. Final Web and wire checks remain valid: no subsequent Web contract changed, and their executive fixture visibility is unchanged by the final non-executive/dependency correction.

Human approval remains Pending. Deployed tenant/SQL Server, controlled external provider, native/physical file or print output, and qualified statutory acceptance from P09 remain independent Unverified gates. These do not prevent P11 implementation against the preserved checkout. No release acceptance is inferred from a build, screenshot or automated test.
