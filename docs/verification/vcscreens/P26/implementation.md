# Annual plan ownership and bindings

`AnnualPlanningService` owns annual governance over native CompanyGoal, QuarterlyReview, OperatingInitiative and C9 Budget identities. It does not manufacture a short OperatingCycle as a year-long plan or recalculate ledger/forecast actuals. Core versions, objectives, milestones, dependencies, budget bindings and allocations are relational. The SQL Server migration creates six tables, company-bound foreign keys, unique request/revision/successor constraints and a state concurrency token.

An annual objective retains the native goal version, metric/unit and recorded baseline; the selected retained quarter supplies partial progress evidence. Progress is `(quarter actual - native baseline)/(annual target - native baseline)*100`. An equal baseline/target yields unavailable progress. It is not represented as a complete annual actual. In the fixture baseline 0, retained Q3 actual 13 and target 100 give 13%; successor target 120 changes the scoped percentage. Four dated milestones must fall inside independently converted company-local fiscal quarters. Missing accountability, unavailable baseline evidence, incompatible calendar/measure/version or currency block preview.

Native Finance budgets use UTC month labels. Month-start fiscal years are supported; other start days explicitly block new budget allocation previews. Each referenced nonnegative expense budget reconciles exactly to objective, investment and explicitly named reserve allocations. Allocation quarters agree with their native budget month. Revenue and expense envelopes are never netted. Budget fingerprints retain row identity, account, month, dimension, version, amount, currency and update time.

Save appends a draft; idempotent retries retain its identity. Predecessor/version and preview fingerprint prevent stale writes. Review requires balanced current bindings and creates the canonical owner-role approval in the same database transaction. Canonical material rechecks objectives, active owners, budgets and fiscal configuration; stale decisions mark the annual version stale. Generic approval creation cannot bypass draft/review or substitute another reviewer policy. Canonical review exposes retained targets/owners/allocations and an exact annual comparison link. Every lifecycle transition is audited. Approval records planning intent only.

The monthly snapshot owner now exposes a read-only transitive access query reused by annual review and approval. No source-reproduction command or audit write is hidden in that permission query. Annual open is an explicit POST reproduction command; current native private-source access is required. Finance and company-performance responsibility are also required. Approved definitions remain readable under current authorized source access when a new draft or mutable live budget is proposed; retained definitions are not rewritten.

Native Year overview and `/dashboard/planning/year` share the workspace. Typed clients validate company, fiscal period, proposal and version identities. Reload/context switches cancel work and clear prior values. The UI binds local milestone dates while preserving unchanged UTC instants, exposes explicit review blocks, canonical approval, prior-versus-proposed detail and retained history. No provider or execution control is added.
