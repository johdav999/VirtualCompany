# P21 implementation

2026-10-05 completion review: the existing capacity calculation now rejects unrepresentable decimal capacity with a validation response while preserving valid fractional assumptions. Retained forecast payloads with missing/null inputs or invalid arithmetic/date values keep explicitly labeled aggregate-only totals. Retained capacity payloads with missing required fields, invalid assumptions or mismatched currency fail reproduction as integrity errors. These changes add no schema, wire contract, UI or calculation-version changes; see `revalidation-2026-10-05/README.md` and its final evidence.

Sales owns the management report at `/app/sales/reports/management` and capacity detail at `/app/sales/reports/capacity`. The native operational pipeline, forecast, activity and message analytics reports retain their definitions. Typed company transport and current Sales responsibility checks apply to management queries, proposal history, save and reopen. Reports and proposals emit no customer assignment, compensation or outbound command.

The management cohort is nondeleted opportunities created in the selected company-local month and preceding month, observed through month end or current as-of. A partial selected month compares the same elapsed prior duration. Won/created conversion and won/(won+lost) win rate count each opportunity once using its last recorded outcome; reopening removes it from decided outcomes. Cycle is creation to the recorded outcome; no mutable updated-date proxy is used. Zero denominators, missing stage IDs, absent event reasons and missing historical ownership/territory are explicitly disclosed. Every included opportunity and recorded event is inspectable. Current open workload and current currency-separated 30/60/90 forecasts remain distinct from the period cohort.

Existing native conversion/stage/won/lost commands now record nullable actor, stage IDs and explicit reason on their existing activity records, atomically with their existing audits and effects. Historical summaries are not treated as recorded reasons and existing rows are not backfilled. Existing forecast persistence additionally captures its original calculation as-of, authoritative `stage-risk-v1` inputs, default/recorded risk and expected contribution. The legacy deterministic primary-currency/daily-replacement behavior is preserved. Legacy captures without inputs or inputs that fail reconciliation are labeled aggregate-only. Current operational reports still expose separate currencies. Movement compares the latest selected-month aggregate with latest earlier capture of the same currency, with coverage carried alongside it.

Capacity proposals retain a bounded report plus selling-hour/workload/territory assumptions and deterministic results. The authenticated reviewer is accountable. Capacity is floor(hours / hours per opportunity), workload is included current open opportunity count × assumed hours, gap is hours − workload, and allocation hours are available hours × target percentage / 100. Unique planning labels must total 100%; they are not actual territory assignments. Immutable private revisions retain hashes, source IDs, timestamps, period/currency, series/predecessor/request identity and notes. Reopening verifies current Sales access and the original inputs/calculation. Unique database indexes enforce request idempotency and one successor per revision; business audit commits with the revision. Payloads are bounded to 512 KiB; cohorts/workload to 2,000 records, events to 20,000, allocations to 20 and notes to 2,000 characters. Large reports require a currency/month filter rather than silent truncation.

P20's monthly composer now retains the owning Sales report alongside the existing workspace. Saved monthly review links open that exact retained payload, including its opportunity/forecast inputs, after the original review's current access and integrity checks. Older P20 reviews with no report remain readable and report detail explains the absence. Source links use the existing Sales journey return helper with exact company/month/currency/snapshot context. Proposal save captures fresh sources as a new revision; the old assumptions and result remain visible.

Migration `20261004140532_AddSalesManagementHistoryAndCapacityProposals` adds nullable fields and the versioned proposal table/indexes only. Downgrade drops P21 additions; it is tested solely in disposable SQL Server databases. No existing financial or operating snapshot is moved. Revisions are retained until company deletion; no separate purge command is exposed.

Two reference prompts were written before generation in `docs/design/references/sales-management-p21-reference-prompts.md`, and both generated references are retained beside it. Images illustrate hierarchy, forms, coverage and revision detail. Their invented sidebar entries, selected person, figures and simplified forecast equation are not production definitions. The existing shell and native Sales stage/risk equation win. Rendered checks are the safe substitute; real visual matching, keyboard and narrow browser acceptance are blocked by the supported runtime's Windows ACL startup failure. No live acceptance is inferred from references.
