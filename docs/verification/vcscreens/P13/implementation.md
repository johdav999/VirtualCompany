`BusinessWorkEvidenceQueryService` is an Operations supervision read model. It resolves existing membership/responsibility/Finance access, validates the actual company-owned record, and joins existing Sales recommendations and Finance handoffs, Support reply drafts/knowledge-gap task links, Finance corrections/payment/enrichment records, and Marketing briefs/variants/channel records. It reuses P10 work and P11 contribution/version/handoff projections. Transitive contribution visibility remains enforced; unauthorized derived work is withheld. Native artifacts retain their recorded review and execution states. Bounded latest-24 work/artifact windows, missing associations and restricted/partial evidence are explicit; failures are instrumented.

Six nullable indexed `WorkTask` business associations cover deal, case, invoice, bill, campaign and brief. Existing payload creators are synchronized on task insertion or material payload update. API task creation validates record existence and current access before persisting. Backfill parses retained JSON safely and joins by both company and ID. Bill identity supports the existing intake (`DetectedBill`) and operational (`FinanceBill`) owners; their retained `SourceDetectedBillId` association is followed only within the company. Intake links open bill review; operational links open supplier-bill detail with `financeSource=operational`. No business lifecycle, grant, approval or execution engine was added.

The typed business endpoint is `GET /api/companies/{company}/agent-work/business/{deal|case|invoice|bill|campaign|brief}/{id}`. Application and Web contracts carry record identity, native artifacts, shared work/contributions, current decision summaries, observation time, workflow meaning, next action and diagnostics. The typed client rejects mismatched identities, incomplete collections, cross-company routes and inconsistent contribution/handoff identity. Cancellation and render generation prevent late requests from overwriting a newly selected record; failures clear old evidence and expose retry.

`BusinessAgentWorkPanel` is reused in Sales deal proposal/Finance tabs, Support case detail, invoice review, intake bill review, operational bill detail, and campaign/content review. Native headings and controls remain primary. Disclosures expose retained versions, output, provenance, gaps, handoffs and actual decision reasons. Exact task/approval/contribution IDs and source context survive navigation. The shared return component updates when navigation changes; collaboration can return directly to a business record while retaining the Sales proposal tab. It invokes no approve/send/publish/post/payment command.

Decision eligibility, concurrency token, stale material binding, durable history and command behavior remain owned by P12/current approval services. Internal task approval yields InProgress; rejection/changes/stale yield Blocked. Neither establishes external execution.
