# P28 review decisions become owned work

Saved monthly findings, quarter objectives, annual decisions/objectives and scenario checkpoints now enter one native Work creation flow. The user selects an active human owner, company-local due date, acceptance outcome, proposed collaborators and constraints, then reviews the exact retained evidence/version and required review before confirmation. The result is an ordinary `follow_up` task created through the existing task command owner, plus relational decision provenance. Collaborators and constraints are proposed context, not agent assignments or execution permissions.

`DecisionWorkService` belongs to Operations, which already owns task and approval commands. It delegates source reads to the original Monthly, Quarter, Annual and Scenario owners; their source reproduction, private-review and department permissions still apply. Web uses separate typed view models and a real wire client. Current membership is checked on every read/mutation; preview fingerprints bind proposal material, current valid assignees and exact source evidence. Superseded sources reject new creation. Retry of an already created command returns the original task, even after a later source revision, subject to current access.

Migration `20261006165512_AddDecisionWorkOrigins` adds `decision_work_origins` and `decision_work_collaborators`. Company-bound typed foreign keys preserve native review/plan/scenario identity, and a check constraint requires exactly one matching source. Unique company/request, company/task and company/source/item keys enforce durable idempotency. The native task, origin, collaborators, audit and platform-event/outbox writes commit together. SQL Server deadlock recovery retries the whole disposed transaction at most twice, with tracked state cleared; it does not replay a partial save. Source and proposal snapshots have integrity checks and remain frozen when source governance or revisions change.

Human work review uses the existing canonical approval owner and decision UI. Creation starts in Review required; submission binds `planning_work_review`, moves the task to Awaiting approval, and records an audit. Approval reviews the objective, accountable owner, due date, outcome, constraints, proposed collaborators and retained source. Starting/completing is denied without the bound approved review. Generic weaker approval requests cannot bypass this binding. These tasks never dispatch agent tools: even an approved work review grants no customer send, publication, financial action or inherited agent policy. Such actions must enter their own current owning workflow and policy/approval/outbox boundary.

Source links on Work reopen the retained creation snapshot and canonical review. Original source views expose work already created from that finding, without a second creation form. Later source versions are shown as notices and never rewrite the owned task. Company switching, late responses, cancellation, errors, DST ambiguity and safe local return routes follow the existing shell/client rules.

Routes: `/work/create-from-decision?companyId=&kind=&versionId=&itemKey=` and `/work/source?companyId=&taskId=`. API: `/api/companies/{companyId}/decision-work` with context, preview, confirm, task open and review commands. Existing `/work?companyId=&taskId=` and `/work?companyId=&tab=approvals&itemId=` remain the owning task and decision destinations.

Local implementation is uncommitted in the original checkout. Production migration deployment, controlled external delivery and named human release approval are separate gates. P29–P30 are outside this request.
