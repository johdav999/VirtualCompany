# Release 3 formulas and reproduction

The owning production definitions remain authoritative. P30 does not add a reporting engine or migration. All money retains its currency; missing evidence remains unavailable. The source fixture is composed from the native P19 and P22-P29 test helpers, rather than production sample data.

| Surface | Definition and retained inputs | Reproduction evidence |
| --- | --- | --- |
| Weekly, all roles | Company-local week boundaries and half-open activity cutoffs. Activity totals count permitted source rows. Current risks and current due schedules retain their observation time; prior pipeline/backlog cannot be reconstructed. | P30 source-reconciliation JSON compares CEO/department definitions, values and source IDs; fixed-clock API tests cover DST, boundaries and absent history. |
| Monthly review | Owning actual/prior/explicit target measures, units and signed variance. Immutable private snapshot includes original inputs, versions, scope and checksum; open/export rechecks current scope. | Five role browser save/reload/export files and API mutation/deletion/revocation/concurrency cases. |
| Sales | sales-management.v1 created cohorts; won/created and won/(won+lost) have distinct denominators. Current forecast = amount × stage probability × (1 − risk × 0.5), with default unknown risk 0.5. Capacity = floor(available selling hours / hours per opportunity); gap = available hours − included open workload. | P21 source reconciliation, P30 Sales browser/revision and integrated native cases. Actual owner/territory history is unavailable; allocation labels are assumptions. |
| Marketing | Native model/version/window allocation evidence; known cost divided by compatible attributed units. Missing cost, conflicting or overlapping cohorts do not become zero or additive credit. | P22 source reconciliation and P30 browser/P22 report, proposal and retained monthly replay. Fixture email cost 100 SEK / 5 attributed leads = 20 SEK per lead. |
| Finance | finance-rolling-planning.v1; posted debit-minus-credit in native UTC monthly boundaries, selected budget/forecast versions and dimensions. Signed variance = actual − selected plan. Future forecast assumptions cannot rewrite closed actuals. | P23 source reconciliation and P30 browser/P23: −1000.10 actual against −1100 budget = 99.90 variance; original and later immutable forecast comparison. |
| Support | support-quality.v1; native lifecycle events and ordered transitions, recorded SLA deadlines and explicit historical coverage. Capacity is a bounded proposal from recorded demand and stated handling/availability assumptions. | P24 source reconciliation and P30 browser/P24; SQL preserves native cases and event history. |
| Quarterly and annual | Retained monthly measures feed native goals and cross-plan initiatives. Explicit resource pools reconcile allocations; annual budget references and allocations reconcile by currency. Fiscal boundaries and owner/milestone versions are frozen. | P25/P26 browser replays and native migration, stale-source, approval and concurrency cases. Governance approval grants no execution authority. |
| Strategic scenarios | Versioned deterministic 3–10-year owning calculation; explicit native annual/Finance baselines, demand/capacity/price/cost growth, cash collection/payment, investment and funding assumptions. Comparison uses compatible saved sources and backend deltas. | P27 formulas in implementation.md, hand-calculated Finance tests, P30 two-scenario browser replay and source/version tests. Saved originals reproduce after live-source change. |
| Owned work and briefings | Typed exact retained source and immutable work preview; native owner review before start/completion. Existing scheduler resolves timezone/work/quiet windows and eligible recipient; native jobs/outbox enforce current scope and duplicate suppression. | P28/P29 browser replays plus Release3IntegratedReviewTests from saved scenario to reviewed work to one timed inbox delivery. |

See the [P30 evidence packet](../P30/README.md) for final results and the [approval checklist](approval-checklist.md) for validation limits. Earlier phase fixture counts may differ when the combined test company adds further legitimate source records; final observed values and versions are recorded rather than copied from older screenshots.
