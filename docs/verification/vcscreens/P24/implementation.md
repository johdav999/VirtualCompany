# P24 implementation and ownership

Native routes are `/support/reports/quality`, `/support/reports/issues` and `/support/reports/capacity`. The existing Support inbox and operational report link to them. `ISupportQualityService` owns report definitions, source aggregation, reviewed grouping revisions, capacity preview and immutable proposal retention. Web clients transport typed contracts; the Web does not recalculate business results. Native Support cases, SLA policies/calendars, knowledge, replies, approvals and agent pause remain authoritative.

Quality uses company-zone half-open monthly cohorts, with the current observed month cut off at report time. Resolution denominator is distinct cases with a native resolution event or committed typed resolution transition in the period. Numerator is those same cases with a later reopening through the report follow-up cutoff, including later months. Typed sequences resolve transitions committed at the same instant; unsequenced same-instant legacy prose cannot prove order. Repeated lifecycle events count once per case. Prior-month results share the follow-up cutoff and therefore have different exposure lengths. The UI and CSV disclose this.

First-response elapsed and business means use answered cases from the arrival cohort. Unanswered durations remain unavailable. Resolution duration is creation to the first recorded resolution in the selected period, including waiting. Business replay uses the selected native calendar and is bounded to ten years; failed replay is logged and excluded, with its sample count disclosed. Native waiting/paused/reopened cases do not reset or suspend SLA targets. Historical backlog is reconstructed only from typed committed states. Unknown balances are unavailable, with known-open and unknown-case counts shown separately. Current category is a labelled grouping suggestion; it is not a historical classification or confirmed cause. Recorded merged aliases are excluded from aggregate cohorts, with source evidence retained.

The additive `AddSupportQualityPlanning` migration adds typed state/merge columns, an optimistic case state revision and two immutable native revision tables. SaveChanges captures successful state mutations from all native mutation paths in the same transaction. Existing imported cases start with a current baseline observation; no historic state is fabricated during report reads. Merge destinations and revision predecessors have company-scoped foreign keys. The migration preserves native cases, event identity/prose, close flags and prior review payloads. Downgrade intentionally removes P24 typed evidence/proposals; normal deployment must retain an appropriate backup.

Shared reviewed grouping corrections preserve source fingerprints, reviewer/reason, predecessor and audit. Private named capacity proposals preserve source rows, calendar, explicit assumptions, original results, checksum and single-successor revisions. Serializable transactions and a company SQL application lock handle duplicate requests and competing revisions; case state changes use optimistic concurrency and return 409 on lost updates. A retry with the same request/content returns its original result; changed content conflicts. Reopening/export requires current membership and Support responsibility. Corrupt evidence returns 422. Current responsibility is also rechecked before a retained company-lens monthly review reveals nested Support detail.

`support-quality.v1` calculates required handling hours `(assumed arrivals + backlog assumption) × handling minutes / 60`. Available productive hours are configured business days (excluding native holidays) × assumed hours/day × available people × utilization/100. Capacity is the floored number of handleable cases; shortfall is positive required-minus-available hours. Required people rounds upward to two decimal places and is unavailable with zero productive business hours. Decimal precision, input magnitudes, target horizon and integer capacity are bounded. The response target is an explicit assumption: arrivals and handling totals do not establish a queue distribution or response-time guarantee. Saving a proposal creates no staffing schedule, execution permission or customer promise.

Reports bound company sources at 2,000 cases and 20,000 lifecycle/grouping records. Partial source coverage is labelled before the values; full backlog, grouping correction, export and capacity calculation are withheld. Aggregation failure uses existing monthly contributor unavailable diagnostics and logging. Native return contracts preserve exact company, source case, selected period/category and retained review/proposal identity. Cancelled or late company responses cannot restore prior sources. CSV uses freshly authorized live rows or original retained proposal values and escapes spreadsheet formulas.

The new nested calendar contract serializes working-day enums numerically so existing P20 monthly clients remain compatible, while accepting numeric or string input. The existing standalone Support calendar endpoint is unchanged. P24 also registers previously omitted P23 rendered/wire files in their explicit project compile lists; their fixtures now use native Finance routes, current number formatting and consistent foreign-company options. Prior P23 evidence remains historical and is not rewritten.
