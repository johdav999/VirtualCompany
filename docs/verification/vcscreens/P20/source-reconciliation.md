# P20 source reconciliation

Monthly measures retain their owning module sources. Finance uses ledger-based statements and recorded fiscal close state; Sales uses nondeleted activity events, currency-separated current pipeline and persisted forecast aggregates; Support uses recorded response deadlines with eligible unanswered breaches included; Company uses the current authorized bounded Work cohort; Marketing retains governed observations. Missing prior balances, targets, reasons and full historical populations are disclosed rather than reconstructed.

Tests reconcile retained JSON and CSV with captured actual/prior/target inputs. Later source correction/deletion does not alter the old payload/hash, refresh creates a new revision, currency mismatch removes the comparison, and exact monthly goal matching supplies targets. Native Work inputs that contributed even to counts are captured and checked against current direct/transitive access. Unauthorized company/user/lens, changed responsibility, payload corruption and unavailable calculations withhold reproduction/export.

SQL Server checks upgrade/down/upgrade without moving native history, enforce one successor under simultaneous refresh, resolve idempotent retries, and reopen all five role reviews after native Sales activity deletion. Test-owned GUID databases are deleted by fixture disposal. Rendered tests cover saved-view replacement, exact source returns, stale async cancellation, retry identity and authorization before CSV Blob handoff. Physical file saving and real-browser appearance are unverified.
