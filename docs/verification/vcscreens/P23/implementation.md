# P23 implementation

Finance owns the enriched monthly account report and deterministic forecast calculation. Existing native variance uses the same difference/percentage helpers; its legacy wire semantics remain usable. Posted ledger lines are actual authority, using the existing posting-date, debit-minus-credit convention. Budget and Forecast versions are explicit, currencies and cost centers are never combined, and prior-year sources are retained separately. Actual-only/history-only rows and absent baselines remain visible with unavailable amounts. Queries do not initialize/seed Finance or fabricate zero results.

The report accepts a bounded monthly horizon, account, cost center, currency, budget/forecast version and optional configured fiscal period. Fiscal period boundaries must exactly match native UTC planning months; the editor rejects overlapping closed periods. Native governed cost-center validation is now one shared owner for budget writes and forecast assumptions. No new conversion rule is invented.

Explanations are append-only, actor/request-audited and tied to a comparable row and source fingerprint. The report labels notes whose evidence changed. Future assumptions require native account currency, active/effective dimensions, unique month/account/dimension keys, two-decimal signed amounts and explicit rationale. Preview calculates once in the Finance application owner. Save refreshes authorization and source evidence, checks the exact preview fingerprint and appends a named immutable revision plus linked native Forecast rows in one transaction. SQL Server uses a company-scoped transaction application lock to serialize duplicate/successor writes and Serializable reads to prevent fiscal/source changes during save. Production execution strategy wraps the transaction. Duplicate requests reproduce original values; changed payloads or an already-used predecessor conflict.

Migration AddFinanceRollingPlanningRevisions adds revision/assumption/audit evidence and explanations, plus a nullable composite tenant FK from native Forecast to its revision. Existing Budget/Forecast values are retained, with no backfill or replacement store. Revisions, linked native rows and explanations are immutable until company deletion. Payloads are capped at one MiB and checksummed; reopening verifies context and recomputes values from original assumptions. Corrupt retained evidence is withheld.

Version comparison aligns retained period/account/dimension/currency values and never substitutes zero for a missing version. Each original actual amount remains distinct; changes compare only future forecast values. Fresh authorized variance CSV and retained comparison CSV use the same server definition and selected scope, with two-decimal formatting and spreadsheet formula escaping.

P20 monthly reviews append optional Finance planning evidence. A unique budget/forecast version is selected explicitly; ambiguous versions remain unavailable. Older snapshots remain supported. Current Finance responsibility is rechecked before nested retained planning can be opened or exported. Source IDs, dates, original rows, selected versions, explanatory notes and coverage are in the immutable review payload. Financial statements, journal posting, period close/lock, payments and statutory semantics retain their existing owners.

Existing Finance agent context resolves exact saved forecast names/native keys through the native resolver, exposes immutable checksum provenance only for authorized Analyze metadata, and uses the original actor/agent/current-authority and freshness gates. No new grant or execution authority is created.

UI routes: `/finance/reports/variance`, `/finance/reports/rolling-forecast`, `/finance/reports/forecast-comparison`. Finance workspace and operational navigation link to them. Period/filter/company and safe previous-view context survive source/detail/revision links. Loading, empty, partial/gap, restricted, validation, stale/conflict, failed/retry and corruption states are explicit. All forecast editing is native Razor/forms; generated raster references are documentation only. Closed actuals, actual budget authority and payments are never changed by forecast save.
