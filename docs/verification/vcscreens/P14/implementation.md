# P14 implementation

The shared `AuthorityExplanationPanel` appears in durable Work detail and `/settings/agents/authority`. The settings hub exposes it without replacing the existing operating-profile destination. Four native labeled, disabled radio positions show company intent and consequences: Advise, Organize, Do internal work, Act within limits. The fieldset is keyboard reachable; Refresh, agent selection and disclosure are keyboard operable. This view has no grant/edit/apply/execute command.

`AuthorityExplanationQueryService` is a scoped query over existing owners. `CompanyWorkVisibility` restricts agent selection and the P10 Work query validates work/transitive scope before authority identities are read. Company limits come from the existing configuration service. Bound operating initiatives/tasks use the current company Dispatch autonomy policy. Unbound work explicitly reports that no separately approved task-type policy or operating plan was evaluated, rather than inventing a policy.

`CompanyAgentToolExecutionService.PreviewAsync` reuses its runtime profile, permission adapters, Finance actor checks, Finance risk context resolution and tool guardrail, without creating attempts/approvals, provider effects or database writes. Individual capability checks use no proposed business payload and are labeled as checks, not complete execution permission. The owning workflow, payload, actor, limits, integration and approvals must still be evaluated at execution. Company ControlledExecution retains external human review. Company/agent/Finance storage values retain separate typed meanings; the presentation maps company values to four positions, agent profile values to their own labels, and Finance levels to named grant semantics.

The existing capability resolver also reports configured entries excluded from the supported catalogue as informational metadata. Executable tools and the existing authority hash remain unchanged. The explanation displays those entries as Unsupported and never grants them. Missing integration, configuration, permission/scope denial and review remain explicit.

Finance grant versions, volume/amount/time/freshness bounds and expiry come from the grant owner. A clearly labeled proactive Finance manual-review/one-action check, with no current business evidence supplied, uses the existing evaluator; missing/stale evidence, expiry, controls and current policy/authority hashes remain authoritative. This receipt is separate from a human-requested tool check. No Finance grant is inferred from the agent profile or company level.

Every request evaluates current state and sends `Cache-Control: no-store`. The versioned projection fingerprint covers displayed company version, profile authority, actor outcomes, grant limits/expiry and policy decisions, excluding observation time. A company-version change during the read produces an explicit inconsistency diagnostic. Evaluation failures are logged by safe failure type and yield an unavailable receipt with no permission claim. The Web typed client rejects foreign identity, missing/unsupported projection metadata and incomplete rows; cancellation/generation prevents an earlier company response replacing current state.

No new authority model or migration was added. P01–P13 identities, decisions, lifecycle, contextual business panels and approved executor/outbox boundaries remain in place.

Standalone settings persists selected agent identity in its query parameter and reloads through the typed current read. Work-context settings returns the exact canonical original Work route, including the original filtered-board return. Native disclosures keep Work's next step visible while exposing full receipts; standalone settings opens the detailed restrictions. Decimal bounds retain recorded punctuation and no currency is invented.
