# Document repositories settings reference prompt

Use case: ui-mockup
Asset type: desktop SaaS settings page reference screenshot
Primary request: Create a high-fidelity reference screenshot for the Virtual Company “Document repositories” settings page. The page lets a company administrator connect and supervise a read-only Microsoft 365 document source used by AI agents.
Scene/backdrop: Virtual Company’s existing desktop app shell with a fixed 240 px white left sidebar, a pale `#F7F9FC` workspace, and a centered content area no wider than 1240 px.
Style/medium: clean modern operational SaaS UI, calm and trustworthy, Inter typography, white rounded cards with soft `#E5E7EB` borders and subtle shadows, blue `#2563EB` primary actions, restrained green/amber/red status colors, no gradients.
Composition/framing: 1536×1024 desktop screenshot. Keep Settings selected in the sidebar. Main header has uppercase “SETTINGS”, title “Document repositories”, a short explanation, and a “Connect repository” primary button. Under the header place a blue-tinted publication-boundary information banner explaining that selected files are published to chosen Virtual Company agents and are not automatically filtered by each viewer’s Microsoft account. Main content is a 2/3 + 1/3 layout. The left column contains one connected SharePoint repository card with source name and safe external-link affordance, read-only badge, healthy connection badge, last checked and last synchronized times, three compact counts for indexed, processing, and failed documents, explicit agent access chips, and buttons for “Sync now”, “Edit access”, and “Disconnect”. Beneath it show a compact empty-state card inviting another approved repository. The right column contains a “What needs attention” action card with one failed-document warning and retry action, plus a “How access works” explanation card. Include a visible connect/configuration panel treatment with grouped fields for Microsoft tenant ID, application ID, secure credential reference, drive/library ID, root folder selection, company audience, and agent checkboxes; communicate that secrets are managed securely elsewhere. Use labels and helper text rather than technical jargon.
Responsive intent: cards stack into one column on narrow screens; actions remain full-width and keyboard/touch reachable; status/count information never relies on color alone.
Text (verbatim): “Document repositories”, “Connect repository”, “Published to Virtual Company”, “Read only”, “Connected”, “Sync now”, “Edit access”, “Disconnect”, “What needs attention”, “How access works”.
Constraints: Answer what is happening and what the administrator should do next. Preserve the existing Virtual Company settings information architecture; do not add a new primary navigation item. Show realistic UI structure but no people, photos, logos, provider secrets, bearer URLs, internal enum values, or raw provider errors. Do not depict a chatbot-first interface.
Avoid: futuristic styling, dark mode, decorative illustrations, dense admin tables, oversized metrics, glassmorphism, gradients, mock browser chrome, watermarks.
