# Sales presentation ad-hoc flow reference prompt

Use case: ui-mockup
Asset type: high-fidelity SaaS product UI reference
Primary request: Design the Virtual Company Sales “Use preset” flow for preparing an ad-hoc customer presentation without an existing meeting or campaign.
Scene/backdrop: Virtual Company production app shell with fixed 240px left navigation, Sales workspace in the center, and Alex Sales Manager insight rail on the right.
Style/medium: realistic desktop web application UI, crisp Inter typography, production-ready rather than conceptual artwork.
Composition/framing: 1440×1100 desktop view. Show Presentation presets selected in Sales navigation. The center workspace contains a compact preset library on the left and a focused “Prepare ad-hoc presentation” panel on the right. Structure the preparation panel as: selected published preset/version summary with three slide thumbnails; optional customer context selectors for account, contact, lead, and deal; presenter, goal, intended audience, duration, language, control mode, and meeting/runtime strategy; a clearly labelled customer-evidence section; authoritative readiness card; and bottom actions.
Text (verbatim): "Presentation presets", "Use preset", "Prepare ad-hoc presentation", "Published version 3", "Customer context (optional)", "Presenter", "Goal", "Intended audience", "Duration", "Language", "Control mode", "Meeting strategy", "Customer evidence", "Needs review", "No customer context selected. Customer-specific claims will remain unavailable.", "Prepare presentation", "Cancel", "Alex · Sales Manager", "Ready after review".
Color palette: light mode with #F7F9FC page background, white cards, #2563EB primary actions, #16A34A success, #F59E0B review warning, #DC2626 danger, slate text, subtle gray borders.
Layout details: 12px card radii, subtle shadows, 16–24px spacing, dense readable form controls, strong section labels, visible inherited-versus-overridden values, one warning card rather than decorative charts. The primary action is Prepare presentation. Opening a live presenter is absent until preparation is authoritative and ready.
Responsive behavior: imply a mobile layout where the library, form sections, readiness, and actions stack in that order with full-width controls and no horizontal clipping.
Constraints: preserve the existing Virtual Company information architecture and executive-control-center tone; make optional context explicit; distinguish reusable preset content from run-specific customer evidence; show that missing customer context requires review and never invents facts; no provider-specific identifiers; no live presentation automatically starts; no gradients, glassmorphism, excessive decoration, logos, watermarks, or unrelated charts.
