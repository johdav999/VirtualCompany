# Sales meeting preset run reference prompt

Use case: ui-mockup
Asset type: production SaaS desktop page reference screenshot
Primary request: Design the existing Virtual Company sales meeting preparation page after adding immutable presentation presets and meeting-specific presentation runs. The user must be able to choose and preview a published preset, see the pinned version, distinguish inherited defaults from meeting overrides, prepare customer-specific briefing evidence, review blockers, compare an available newer version before explicitly updating, save an eligible direct-upload setup as a preset draft, retain the legacy PowerPoint upload path, and open the presenter only when the authoritative run is ready.
Existing product context: Virtual Company is a web-first executive control center where AI agents operate the company and a human supervises decisions. Preserve the established app shell with a fixed 240px left navigation, a central Sales workspace, and a narrow right-side AI insight/action rail. Sales navigation includes Overview, Prospects, Pipeline, Campaigns, and Presentation presets. This is a detailed workflow reached from an individual scheduled meeting.
Scene/backdrop: light SaaS application background #F7F9FC with white cards, subtle borders and shadows.
Style/medium: realistic shippable Blazor SaaS product UI, not concept art; Inter typography; restrained blue #2563EB primary, green #16A34A ready state, amber #F59E0B review state, red #DC2626 blockers.
Composition/framing: 16:10 desktop viewport. Header contains breadcrumb, meeting/customer title, scheduled time, and a compact readiness state. Main content uses a two-column workspace: wide left column for a preset selector and slide preview followed by customer preparation evidence; narrower right column for presenter/defaults/overrides and authoritative readiness. Use 12px-radius cards and 16px padding. Include a compact pinned-version badge and a clearly separated “Meeting overrides” section with inherited-value indicators. Include a visible but secondary “Upload a presentation instead” disclosure. Put “Prepare presentation” or “Open presenter” as the single dominant action based on readiness. Right insight rail calls out that version 4 is available and offers “Review changes”, never silently updates. Show a small update comparison panel with changed duration and goal plus preserved override markers. Include loading/progress affordance and an actionable blocker example.
Responsive behavior: imply that at mobile width the columns and insight rail stack into one logical sequence, selectors and actions become full width, and slide preview remains readable without horizontal overflow.
Text (verbatim): “Meeting preparation”, “Presentation preset”, “Pinned to version 3”, “Meeting overrides”, “Customer preparation”, “Ready to present”, “Version 4 is available”, “Review changes”, “Save setup as preset”, “Upload a presentation instead”, “Open presenter”.
Constraints: strong information hierarchy; accessible contrast; visible keyboard focus; practical controls; distinguish reusable preset content from customer-specific preparation; do not expose enum names or provider internals; no invented customer facts; no logos, trademarks, decorative charts, stock photos, gradients, glassmorphism, or watermark.
