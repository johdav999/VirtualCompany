# Production-path benchmark driver contract

The coordinator invokes the configured driver once, passes a JSON request on standard input, and expects one sanitized JSON evidence document on standard output. The driver must operate the deployed Virtual Company browser-room API and LiveKit media path. It must not call AI providers directly or implement narration, question answering, approval, cache or floor logic.

The request contains the reviewed run plan, ordered authorized concurrency steps, frozen fixture and dated rate snapshot. Run an idle baseline, then paired concurrency-1 A/B calls before any higher step. Exercise every narration arm at concurrency 1; exercise English/Swedish and both input policies at 10/30/60 percent duty. Scale matched live-generated/cached runs through only the authorized steps. Stop immediately when projected spend would exceed the envelope, any quality/latency threshold fails, a queue grows after drain, frames drop, an application instance restarts unexpectedly, or provider capacity rejects the step.

Each call result records its arm, cache phase (`cold`, `warm`, or `partial_revision`), language, policy, duty cycle, quality result, exact fixture/audio hashes, received/detected/forwarded/provider-billed audio, generated/played/cancelled output, cache hit/miss and narration generation request count, retries/failures, sanitized provider request/session references, usage-event IDs and the four latency sample arrays. Record all attempts, including failed and cancelled calls.

Usage events require a stable `event_id`, vendor, category, quantity, unit, and either actual reconciled `cost_usd` or `unit_rate_usd`. Set `unit_size` when the rate is quoted per multiple units, such as `1000000` for a per-million-token rate; it defaults to one. Replayed identical events are accepted once; conflicting duplicates invalidate the report. If OpenAI is called directly, mark OpenAI as the billing vendor. If LiveKit Inference is the billing vendor, do not also submit the underlying model charge.

Each capacity step supplies matched idle/loaded CPU seconds, integrated active-call seconds, working-set and allocated bytes, network/storage usage and operations, application instance identities/count, scale events, queue start/peak/end, dropped frames, restarts, drain outcome, incremental Azure cost and its evidence reference. Sample platform state at one-second resolution and keep the load generator on separate resources. Record the existing fixed hosting cost and a concrete allocation assumption separately. If invoice reconciliation is unavailable, list the unresolved estimates.

Secrets, bearer tokens, raw provider payloads, invitation credentials, participant audio and customer data are forbidden in output. Teams routes and resources are forbidden benchmark targets. The coordinator writes immutable evidence and a derived report; the driver must delete only rooms and synthetic records it created and report cleanup failure.
